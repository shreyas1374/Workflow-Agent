# AI Agent Workflow Builder

Multi-tenant AI Agent Workflow Automation Platform built with Next.js, Nhost, Hasura, PostgreSQL, and GraphQL.

---

## Authorization & Role Architecture (Checkpoint 3)

### 1. Hasura Role Model vs Application Roles
- **Hasura Session Role**: All authenticated client requests use Hasura's standard `"user"` role (`X-Hasura-Default-Role: "user"`). We do **not** create static global Hasura roles like `owner`, `editor`, or `viewer` in Hasura JWTs.
- **Application Roles in `org_members`**: Organization-specific roles (`owner`, `editor`, `viewer`) are stored dynamically in the `org_members` database table per user per organization.
- **Dynamic Relational Authorization**: Every Hasura permission rule for role `"user"` queries `org_members` via object relationships to verify the caller's `user_id` and specific role for the target resource's organization.

## Phase 1 - Nhost Setup

This repository represents **Phase 1 (Nhost Setup Foundation)**. The objective of Phase 1 is to establish Nhost Authentication, verify PostgreSQL availability, and confirm Hasura GraphQL Engine access.

---

### 1. How to Create and Configure the Nhost Project

1. Log into your [Nhost Dashboard](https://app.nhost.io).
2. Click **Create Project**.
3. Choose a project name (e.g., `ai-agent-workflow`) and select a database region.
4. Once the project finishes provisioning, navigate to **Project Settings -> App Info**.
5. Copy your **Subdomain** and **Region**.

---

### 2. Required Environment Variables

Create a file named `.env.local` in the root of the project (refer to `.env.local.example`):

```bash
# Nhost Configuration
NEXT_PUBLIC_NHOST_SUBDOMAIN=your-nhost-subdomain
NEXT_PUBLIC_NHOST_REGION=us-east-1

# Optional Custom Backend URL (for self-hosted or proxy setups)
# NEXT_PUBLIC_NHOST_BACKEND_URL=https://your-nhost-subdomain.nhost.run
```

> **Security Note:** Never commit secrets or API keys to Git. Environment variables starting with `NEXT_PUBLIC_` are safely exposed to the client bundle for Nhost Auth SDK initialization.

---

### 3. How to Run the Next.js App Locally

Install dependencies and start the development server:

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

---

### 4. How to Create a Test Nhost User

You can create a test user in two ways:

#### Option A: Direct Sign Up via the Web App
1. Navigate to [http://localhost:3000](http://localhost:3000).
2. Toggle to the **Sign Up** tab on the Authentication card.
3. Enter a test email (e.g., `alice@orga.com`) and a strong password.
4. Click **Create Nhost Account**.

#### Option B: Via Nhost Dashboard
1. Go to your Nhost Dashboard -> **Users**.
2. Click **Add User**.
3. Fill in email (e.g., `alice@orga.com`) and password.

---

### 5. How to Verify Login and Logout

1. Navigate to [http://localhost:3000](http://localhost:3000).
2. On the **Sign In** tab, enter your test user's email and password.
3. Click **Sign In with Nhost**.
4. Upon successful authentication, the UI will update to show:
   - User ID (UUID generated by Nhost Auth)
   - User Email
   - Verification status
   - Default Role (`user`)
5. Click **Log Out** to terminate the session and confirm that the login card reappears.

---

### 6. Where to Access Hasura & Verify PostgreSQL

1. Open your Nhost Dashboard.
2. Select your project and click **Hasura** in the left sidebar (or click **Database**).
3. The Hasura Console provides access to your PostgreSQL database schema (`public` and `auth`).
4. Your Hasura GraphQL endpoint is accessible at:
   `https://<your-nhost-subdomain>.hasura.<your-region>.nhost.run/v1/graphql`

---

### 7. What Has Intentionally NOT Been Implemented Yet

To preserve modularity and satisfy checkpoint boundaries:
- **No Hasura Actions** (`triggerWorkflowRun`, `approveStep`) or **Event Triggers** have been defined yet.
- **No workflow execution engine**, LLM integration, or external HTTP step runners have been written yet.
